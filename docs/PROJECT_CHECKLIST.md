# One-Page Project Checklist

**Goal:** finish on time. Decide first, build the basics, stop adding things.

---

## 1. Before you start (about 1 hour)

- [ ] **Must-have list:** write 5–10 items. Nothing else gets built.
  1. ______________________
  2. ______________________
  3. ______________________
  4. ______________________
  5. ______________________
- [ ] **"Later" list:** every new idea goes here, not into the build.
- [ ] **Time budget:** ______ hours, plus 20% for bugs = ______ hours total.
- [ ] **Finish date:** ______________
- [ ] **Keep it simple:** pick the fewest tools, logins and moving parts.
- [ ] **Look decided:** choose colours and fonts once, up front.

## 2. While building

- [ ] **Work first, pretty later.** Get it live and usable, then polish.
- [ ] **Small slices.** Finish one thing fully (screen, data, test) before the next.
- [ ] **Time cap per task.** If it runs over, stop and ask: is this worth it?
- [ ] **One pass per screen.** No repeated "rounds" on the same screen.
- [ ] **Long work blocks.** Several days in a row, not one day a week.
- [ ] **Docs once a day.** Keep notes short; no note update after every task.

## 3. Halfway check

- [ ] **Put it live and test it for real** (real database, real logins, real phone).
- [ ] **Compare hours used vs. budget.** Over 50% used and under 50% done? Cut something.

## 4. Weekly check (5 minutes)

Ask: **"Is everything I added this week on the must-have list?"**
- [ ] Yes → carry on.
- [ ] No → move it to "later" or remove a must-have to make room.

## 5. Finish line

- [ ] Every must-have works on the live site.
- [ ] Tests and checks pass.
- [ ] Short notes written (how to run it, how to fix common problems).
- [ ] **Stop.** Anything left goes to version 2.

---

### Red flags (stop and re-plan if you see these)
- The task list keeps growing.
- You are redoing a screen for the third time.
- You are working on looks while a must-have is unfinished.
- Hours used are past the budget and the must-have list is not done.
